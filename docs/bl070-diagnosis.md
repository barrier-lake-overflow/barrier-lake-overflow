# 草嶺（bl070）漏報診斷

> 2026-10-29。只查原因，沒有改偵測程式。
> 重現：`cd code && python scripts/diagnose_missed_lake.py --lake bl070 --day 20250708 --later 20250720`
> 產出：`docs/evidence/bl070_diagnosis_20250708.png`、`docs/results/bl070_diagnosis_20250708.json`

## 結論

**草嶺漏報是衛星重訪的限制，不是遮罩或門檻的問題：湖從堵塞到溢流的一天多裡，沒有任何衛星（Sentinel-1 升降軌、Sentinel-2、Landsat）過境。回放用的那一期（7/8 18:01）落在堵塞前後，湖還沒蓄水；之後最早的雷達影像是 7/11 清晨的降軌，湖已在消退。**

設計文件原本推測「湖面大多沒有低到門檻，剩下的又落在陡坡遮罩裡」。實際拆解後發現，被遮罩擋掉的像元都在**別的地方**；預期的湖區本身幾乎沒被遮罩，雷達上看起來就是陸地。

## 證據

### 1. 預期湖區在 7/8 的雷達影像上是陸地

用事件前 DEM 從壩址往上游淹水，水位調到清冊蓄水量 1,400 萬 m³，得到預期湖面：**約 84 公頃，水位約 557 m，位在壩址東南方的谷底**（圖右下青框）。這是粗估，事件前 DEM 沒有壩體，只用來判斷湖大概在哪裡、多大。

| 預期湖區內 | 數值 | 如果是水 |
|---|---|---|
| 7/8 σ⁰ 中位數 | −7.2 dB | 低於 −18 dB |
| 事件前 σ⁰ 中位數 | −7.8 dB | — |
| 變化中位數 | +0.6 dB | 明顯下降 |
| 低於 −18 dB 的比例 | 0.2% | 大部分 |
| 被判水遮罩擋掉的比例 | 1.2% | — |
| 坡度中位數／坡度 ≤ 20° 的比例 | 9°／89% | — |
| 7/20 低於 −18 dB 的比例 | 0.7%（湖已消失） | — |

預期湖區是平緩的谷底，遮罩幾乎沒有作用；只要那裡有平靜水面，流程應該抓得到。但 7/8 那一期，這一帶的背向散射跟事件前幾乎一樣。

壩址周圍有明顯**變亮**（+6～8 dB，圖右上藍色），符合新的崩塌堆積，表示 18:01 時崩塌可能已經開始或已發生，只是湖還沒蓄水。湖從堵塞到溢流約一天（7/8 晚間 → 7/9 18:20），7/8 18:01 最多只是剛開始積水。

### 2. 全窗格的低值像元被擋在哪裡

4 km 窗格內「事件後低於 −18 dB、事件前沒有」的像元，逐關拆解（與正式流程同一套函式與參數，最後結果與 `final_inv_bl070_20250708.json` 一致）：

| 關卡 | 面積（公頃） |
|---|---|
| 遮罩前，低於門檻的新像元 | 5.30 |
| 　被陡坡（> 35°）擋掉 | 3.47 |
| 　被雷達陰影擋掉 | 0.16 |
| 　被疊置擋掉 | 0.00 |
| 遮罩後剩下 | 1.67 |
| 　坡度雙門檻（整塊都在 20° 以上）擋掉 | 0.81 |
| 雙門檻後剩下 | 0.86 |
| 　面積不足 0.5 公頃擋掉（最大一塊 0.40 公頃） | 0.86 |
| 候選 | 0 |

這 5.30 公頃大多是窗格裡零散的陡坡像元（圖下中紅點），落在預期湖區內的只有 0.16 公頃。所以「被遮罩擋掉」不是漏報的原因：就算把遮罩全部拿掉，湖區也沒有低值像元可抓。

### 3. 湖存在期間沒有任何衛星拍到

用 `code/scripts/gee_check_bl070_passes.js`（GEE 網頁版）列出 2025-07-06～07-21 涵蓋壩址的所有影像：

| 時間（台灣） | 衛星 | 與湖的關係 |
|---|---|---|
| 7/8 10:41 | Sentinel-2 | 堵塞之前；整景雲量 100%，壩址周圍沒有晴空 |
| **7/8 18:01** | **Sentinel-1 升軌 69** | 堵塞前後，湖還沒蓄水（回放用的這一期） |
| 7/8 晚間～7/9 18:20 | — | **湖蓄水到溢流：沒有任何影像** |
| 7/11 05:52 | Sentinel-1 降軌 105 | 溢流後約 1.5 天；報導指湖水約一天內溢流回河道，7/11 空拍幾乎退光 |
| 7/13 10:26～10:41 | Landsat 8/9、Sentinel-2 | 湖已消失 |
| 7/14、7/17、7/18、7/20 | Landsat、Sentinel-1、Sentinel-2 | 湖已消失 |

湖蓄水的那一天多（7/8 晚間～7/9 傍晚）**沒有任何 Sentinel-1、Sentinel-2 或 Landsat 影像**。降軌 105 最早是 7/11 清晨，湖已在消退中，回放就算改用降軌（或兩軌都用）也只會看到排空後的殘餘。所以這筆漏報不是「每湖只用一軌」的回放規則造成的，而是衛星重訪本身的限制：存續不到兩天的湖，Sentinel-1 一軌 12 天、兩軌交錯約 6 天的重訪，很可能整段錯過。

降軌 7/11 的影像沒有下載分析；如果要看排空後的殘餘水面，可以補抓這一期。

## 問答用的一句話

「草嶺的湖只存在約兩天：7/8 晚間堵塞、隔天傍晚就溢流。我們查了那幾天所有的雷達和光學衛星，湖蓄水的那一天多完全沒有衛星經過；7/8 傍晚那一次過境時湖還沒蓄水，雷達上那一帶還是陸地。這是衛星重訪間隔的限制，不是演算法沒看到。」
